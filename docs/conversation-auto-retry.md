# Codex 容量不足自动重试

通过服务器原生实时通道连接的 Codex 会话，出现 `Selected model is at capacity`、`server_overloaded` 等明确的临时容量错误时，会在原会话继续未完成任务。首次失败后分别等待 10、20、40 秒，最多自动重试 3 次（不包含首次执行）。不会自动切换模型。

错误卡片显示倒计时、当前次数、恢复成功或已达上限，并提供“停止自动重试”。停止只取消后续自动重试，不中断正在执行的任务。用户手动发送新消息、原生队列出现新消息、会话结束/更换绑定或权限被撤销时，取消待重试。

服务端监听已绑定的运行中会话；切换标签或关闭浏览器不影响检测和已安排的重试。重试预算保存在 SQLite `conversation_retries` 表，刷新页面、多个浏览器以及服务重启不会重新计数。历史错误回放不会触发新的任务。原生 `willRetry` 表示 Codex 自行重试，平台等待其结果，不并行重发。

每次重试前核对最新原生 turn 仍为相同的容量失败、线程空闲且没有排队消息；已有正式结论时不再次执行。重试发送带稳定关联编号的继续通知，要求检查已完成及结果未确认的操作，保留原模型、权限、目录和上下文。不是重新提交原始任务。原生接口没有原子的“重试指定失败 turn”操作，用户同时在原始终端输入时仍以原生线程的最终处理顺序为准。

登录、权限、模型配置、额度等错误不自动重试。连接丢失或提交结果不确定时停止自动重发；服务重启遇到提交中的记录，仅在原生关联编号确认已接受时恢复观察。嵌入式或未加载到当前原生服务的 CLI 不会被另外启动。此功能不为检测错误而调用模型，不增加前端网络轮询；实际重试会消耗所选模型的额度。

取消接口：`POST /api/sessions/:id/conversation/retry/cancel`，要求该会话访问权及 `agent_api:write`。状态通过现有 conversation WebSocket 的 `retry` 帧推送。
