# Codex 容量不足自动重试

通过服务器原生实时通道连接的 Codex 会话，出现 `Selected model is at capacity`、`server_overloaded` 等明确的临时容量错误时，会在原会话继续未完成任务。首次失败后分别等待 10、20、40 秒，最多自动重试 3 次（不包含首次执行）。不会自动切换模型。

错误卡片显示倒计时、当前次数、恢复成功或已达上限，并提供“停止自动重试”。停止只取消后续自动重试，不中断正在执行的任务。用户手动发送新消息、原生队列出现新消息、会话结束/更换绑定或权限被撤销时，取消待重试。

服务端监听已绑定的运行中会话；切换标签或关闭浏览器不影响检测和已安排的重试。重试预算保存在 SQLite `conversation_retries` 表，刷新页面、多个浏览器以及服务重启不会重新计数。历史错误回放不会触发新的任务。原生 `willRetry` 表示 Codex 自行重试，平台等待其结果，不并行重发。

每次重试前核对最新原生 turn 仍为相同的容量失败、线程空闲且没有排队消息；已有正式结论时不再次执行。重试发送带稳定关联编号的继续通知，要求检查已完成及结果未确认的操作，保留原模型、权限、目录和上下文。不是重新提交原始任务。原生接口没有原子的“重试指定失败 turn”操作，用户同时在原始终端输入时仍以原生线程的最终处理顺序为准。

登录、权限、模型配置和订阅额度错误不会触发同账号容量重试。连接丢失或提交结果不确定时停止自动重发；服务重启遇到提交中的记录，仅在原生关联编号确认已接受时恢复观察。嵌入式或未加载到当前原生服务的 CLI 不会被另外启动。此功能不为检测错误而调用模型，不增加前端网络轮询；实际重试会消耗所选模型的额度。

取消接口：`POST /api/sessions/:id/conversation/retry/cancel`，要求该会话访问权及 `agent_api:write`。状态通过现有 conversation WebSocket 的 `retry` 帧推送。


## Codex 订阅额度耗尽

平台通过受管 Codex 原生通道识别 `usageLimitExceeded` 和明确的订阅额度错误。普通限流、临时过载和 API 余额错误沿用各自的行为。

| 发生位置 | 平台处理 |
| --- | --- |
| 投递前已确认额度为零，或原生接口明确拒绝本次提交 | 简要压缩后在同一标签页换号，使用同一输入标识投递原消息 |
| 本轮执行已开始 | 确认最新一轮确因额度失败且没有最终答复后，先简要压缩，再换号发送接续指令 |
| 额度错误发生在协作或定时触发的任务中 | 使用同一套受管换号能力，协作批次随标签页绑定接续 |
| 无可用账号、历史无法读取、已有原生排队输入，或无法确认是否已经提交 | 在状态或回执中显示失败原因，保留原记录及待处理输入 |

会话对话实时显示已耗尽额度的账号和选中的备用账号，并随整理简要历史、切换和确认新绑定更新。执行中的额度失败沿用错误卡片和取消操作，发送前、协作或定时任务触发的换号显示在输入区上方。账号名称使用平台配置的显示名。会话所有者重新连接时，可恢复进行中或刚结束的换号提示。切换成功只确认标签页已绑定新账号，接续任务以实际提交回执为准。

服务端监听已绑定会话，浏览器关闭后仍可换号。错误事件先抵达时，短暂等待原生轮次状态和错误详情同步。原生队列已空且最新轮次确认接收了对应输入时，清理已消费的队列标记。换号沿用原会话的权限和当前模型，候选必须通过项目与账号检查。旧对话保留在项目历史。接续指令要求先核对已完成和结果未确认的操作，以免重复执行。平台按原生会话和失败轮次记录接续状态，进程重启后不会重复派发可能已经提交的接续。仅有终端文本、缺少原生事件的会话无法确认失败轮次。
