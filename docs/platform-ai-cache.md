# 平台 AI 上下文缓存

模型请求固定使用相同的系统提示和工具定义。当前时间、近期任务快照放在本轮用户消息末尾，首次处理时写入 checkpoint；工具调用续轮与失败重试不会重新生成这些字段。运行上下文只供平台 AI 使用，用户原文及转发给工作 Agent 的需求不变。

对话保留实际的用户消息、工具调用、工具结果和最终回复。每轮只追加消息，不再逐轮移动二十条消息的窗口；历史序列化后超过 64,000 字符时，按完整用户轮次成批清理到 32,000 字符以内，始终保留最新一轮。压缩边界、图片数量限制和配置变更仍可能降低缓存命中率。

服务端 `Platform AI model usage` 日志记录 `kind`（conversation/observation）、消息或任务编号、模型名称、`prompt_tokens`、`completion_tokens`、`cached_tokens` 和 `cache_miss_tokens`。未返回缓存统计的接口记为 null，不能当成零命中。输入缓存命中率按 `sum(cached_tokens) / sum(prompt_tokens)` 计算。日志不记录提示正文或密钥。流式请求读取到 `[DONE]` 或正常 EOF，兼容最终回复帧和单独 usage 帧。

DeepSeek 缓存要求前缀一致，缓存构建和回收是服务端行为；无法保证每次命中。见 [DeepSeek 上下文硬盘缓存](https://api-docs.deepseek.com/zh-cn/guides/kv_cache/)。

2026-10-22 在当前配置接口上用同一组历史、工具定义和 16 token 输出上限做三轮对照，预热后两轮均为：

| 请求结构 | 输入 token | 命中 token | 命中率 |
| --- | ---: | ---: | ---: |
| 时间放在系统提示末尾、历史之前 | 2,590 | 1,280 | 49.4% |
| 固定系统提示、时间移到本轮消息末尾 | 2,591 | 2,432 | 93.9% |

该结果只代表这组对照请求，不能等同于整个平台或其他 API Key 使用方的命中率。首轮冷缓存也会影响统计。

队列可靠性：启动时会补齐已有项目通知 watch 表缺失的 `rechecks` 字段；调度同步、会话处理、观察和投递分别捕获异常，同一组件连续错误最多每分钟记录一次，避免可选模块故障阻断对话。
