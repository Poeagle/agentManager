# 平台 AI 与外部渠道

平台 AI 是平台的通用交互入口：用户可以查询项目和会话、下发开发需求、读取状态、管理定时任务。项目内的 Codex/Claude 继续负责实际工作。平台订阅已有的标签页状态/活动/退出事件，对关联的待汇报任务触发 Agent API 读取，不要求工作 Agent 主动回调。

功能默认关闭。未配置模型和渠道凭据时，不连接外部渠道，也不会启动开发 Agent。

## 隔离开发

在 feature worktree 中运行：

```bash
npm run dev:platform-ai
```

默认前端监听 `0.0.0.0:43221`，支持局域网访问；后端仍仅监听 `127.0.0.1:43220`，由前端代理连接，数据库和项目配置位于当前 worktree 的 `.test-data/platform-ai-dev/`。端口已占用时直接退出，不结束已有进程。可以用 `DEV_API_PORT`、`DEV_UI_PORT` 选择其他端口；设置 `DEV_UI_HOST=127.0.0.1` 可仅允许本机访问。

`AGENTMANAGER_RUNTIME_NAMESPACE` 隔离登录 Cookie、tmux server、dtach socket、PTY 管道和 systemd sandbox 名称；开发启动器还使用独立的 Vite 缓存。未设置时保留现有生产名称。此启动器不会导入生产数据库、用户或项目。需要在新实例创建管理员，并注册专用于开发的项目目录；不要把正在被生产 Agent 修改的工作目录用于并行开发。

模型、渠道凭据和通知地址均单独配置，不从生产环境复制。API Key 和渠道凭据使用 AES-256-GCM 加密，密钥为数据库目录下权限 `0600` 的 `.platform-ai.key`。备份/迁移时必须同时保留数据库和此密钥；密钥丢失时不会静默生成新密钥覆盖已有配置。

## 使用

1. 从顶部“平台 AI”或“平台管理 → 平台 AI”打开功能。
2. 管理员在“模型配置”填写兼容 Chat Completions 的 API 地址和 Key，点击“获取模型列表”，选择模型，也可手动输入名称。点击“测试连通性”，确认模型响应和工具调用测试通过后，再保存并启用。
3. 可先在网页对话中查询项目、创建后台开发任务并查看“任务跟踪”。
4. 在“渠道与用户映射”配置渠道和外部身份映射，再启用渠道。
5. 回调地址为渠道页面显示的路径；使用反向代理将该路径通过 HTTPS 暴露给渠道平台。不要为接入渠道额外公开终端或管理接口。

### 项目自动通知

打开“平台 AI → 项目通知”，选择项目和接收渠道，勾选“任务完成时通知”和／或“需要输入时通知”后保存。每条规则属于当前用户，只关注该用户在指定项目下的会话，包括之后新建的标签和已绑定 Agent 的终端。无需为每个标签登记任务；同一项目可添加多个接收渠道。接收渠道来自管理员已经配置的当前用户外部身份绑定或企业微信群通知订阅，不需要向普通用户开放渠道凭据管理权限。

后台通过现有会话状态、活动和退出事件触发读取；交互确认直接入通知队列，公开最终答复由平台 AI 判断为完成、提问或继续工作。通知保留 Agent 原文，不把空闲、退出或普通输入框当作任务完成。立即通知表示事件触发后开始处理，送达时间仍受模型响应、渠道连接及重试影响；平台 AI 和接收渠道均须启用。原生日志延迟写入会短时复查，30 秒兜底检查用于恢复漏失事件。

通知规则、观察状态和去重记录保存在 SQLite，重启后恢复；启用或重新启用前的历史最终答复不会补发。与已有任务跟踪使用同一渠道、关联同一请求时，由原任务跟踪负责通知，避免重复发送。可编辑事件开关、暂停、重新启用或删除规则。“通知记录”可查看队列与投递结果；观察读取或模型错误也会显示在规则的状态栏中。投递前再次检查用户、会话归属、项目权限、规则和接收绑定，已撤销的通知不会继续发送。

平台 AI 的模型配置独立于 Codex/Claude。能力目录从实际注册路由生成完整 API 清单，并按需提供已有 Agent API 的参数契约。普通 JSON 状态查询可以直接调用；凭据/身份配置、WebSocket 和二进制接口使用专用入口，写操作通过已声明的命令工具或契约调用。

工具通过一次性内部 Cookie 调用现有 Fastify 路由，继承真实用户的 RBAC、项目、会话归属和工具权限；Cookie 不发送给模型或外部网络。外部群聊以发送者身份隔离上下文，而非将整群映射到一个管理员。

网页对话会自动探测平台当前支持的 Codex/Claude 启动命令，展示“命令可用／未找到／待验证”。探测使用与会话一致的交互 Shell 查询命令，不运行 Agent、不安装软件；命令存在不代表已经登录或具备模型权限。自定义包装命令标记为待验证。AI 的能力目录包含探测结果，派发前还会按项目目录重新校验，不会为明确缺失的命令创建会话。用户明确指定了不可用的 Agent 时，应说明情况并询问替代方案。

网页回复使用流式传输，逐步显示文本，并展示等待模型、探测 Agent、调用平台接口、启动工作会话、整理结果等阶段。部分文本和当前阶段保存到数据库；刷新或重连后可恢复状态。浏览器通过经过身份及对话归属校验的 SSE 接收更新，连接中断时仍保留定时读取。模型服务不支持流式时会在明确拒绝流式请求后回退到完整回复，期间仍展示处理阶段；半途断流的回复不会当作最终结果，也不会执行未完成的工具参数。

模型配置需要 `settings:write`，使用 AI 和工具调用需要相应 `agent_api` 权限。渠道配置和用户映射另外需要 `roles:write`，因为绑定外部身份会赋予其对应平台用户的操作能力。

模型列表探测调用同一 API 基地址下的 `GET /models`，API 地址也可填写完整 `/chat/completions` 路径。部分服务不提供列表，此时可手动填写名称并直接测试。列表可见不代表模型支持平台调度。

探测和测试使用当前表单，无需先保存或启用，也不会修改已有配置。API Key 留空时可复用相同接口地址下已保存的密钥；地址更改后需重新输入 Key。密钥仅由后端发给配置的模型服务，不返回浏览器。连通性测试分别展示接口可达、普通回复和结构化工具调用结果，通常发送两次小型请求，可能产生少量 API 费用。工具测试校验随机参数，不调用平台工具或创建开发任务；测试通过只说明本次基本协议可用，不替代供应商稳定性和实际任务验收。

## 已实现的渠道

| 渠道 | 接入 | 出站通知 | 外部用户标识 |
| --- | --- | --- | --- |
| 企业微信自建应用 | 文本消息回调、URL 校验、AES 解密、签名与应用身份校验 | 应用文本消息 | 成员 UserID |
| 企业微信智能机器人 | 官方 SDK 长连接认证、文字/图片/图文混排、流式回复 | 原会话主动 Markdown 通知 | 回调中的 userid，可能为加密身份 |
| 企业微信群机器人 | 仅出站 Webhook；指定平台用户的任务通知订阅 | 群文本消息 | 不接收入站指令，无身份绑定 |
| QQ | 官方机器人 Webhook，Ed25519 验签和验证握手，C2C/群 @ 文本 | 在允许窗口被动回复，超出窗口尝试主动发送 | user_openid / member_openid |
| 微信 | 公众号文本回调，明文签名或安全模式 AES 验签解密 | 客服文本消息 | 公众号 OpenID |
| 通用 Webhook | 时间戳 + HMAC-SHA256 签名的统一消息 | 对管理员配置的固定地址发送签名 JSON | 网关定义的稳定用户 ID |

微信指公众号入口，不是个人微信账号。QQ 主动消息、公众号客服消息均受各自平台账号权限、额度和互动时限约束。失败保留在“通知记录”，自动退避重试，达到次数上限后标记失败。长文本在原渠道精简，完整内容保留在平台对话中。

企业微信智能机器人支持图片消息、图文混排和文字引用的图片：消息先持久保存，临时图片立即下载解密并保存，网页可查看缩略图和原图。每条最多 4 张，每张最多 8 MB，支持 PNG/JPEG/GIF/WebP。图片读取接口校验登录和对话所有者；临时媒体地址与解密密钥不返回前端或发给模型，接收完成后移除。

配置的模型支持视觉时，会收到真正的图像输入；接口明确拒绝图片时，保留附件并明确说明无法直接识图，继续处理文字需求。派发开发任务可把当前消息或同一对话中指定的原图复制到目标项目，向工作 Agent 提供本地图片路径。普通模型连通测试不验证视觉能力。

其他渠道当前仍只接文本。语音、通用文件附件、企业微信智能机器人 HTTP 回调模式、QQ WebSocket 网关和个人微信桥接尚未实现。真实渠道上线前需要使用对应账号进行收发联调；自动化测试使用签名回调样本、模拟 HTTP 服务，以及官方 SDK 连接本地 WebSocket 对端，不代表已经通过腾讯侧账号审核或实际投递验证。

企业微信三种入口的配置步骤见 [企业微信接入指南](./wecom-integration.md)。

### 通用 Webhook 协议

入站 HTTP POST，`Content-Type: application/json`：

```json
{
  "message_id": "channel-message-id",
  "user_id": "external-sender-id",
  "chat_id": "external-conversation-id",
  "content": "列出我能访问的项目"
}
```

请求头：

```text
X-Platform-Timestamp: <Unix 秒时间戳>
X-Platform-Signature: <hex HMAC-SHA256(secret, timestamp + "." + rawBody)>
```

签名针对原始 UTF-8 请求体，不重新序列化；时间戳容忍五分钟。消息持久保存和去重后才确认接收。签名密钥至少 32 字符。

出站使用相同签名算法，JSON 包含 `delivery_id`、`chat_id`、`user_id`、`content`。`Idempotency-Key` 和 `delivery_id` 在重试时不变，接收网关必须据此去重。签名涵盖时间戳和原始请求体。回复地址只能由管理员在渠道配置中指定，入站消息不能指定任意出站 URL。

## 执行和恢复语义

```text
Signed callback / Web chat
            |
      Durable inbox
            |
  Conversation FIFO + AI tools
            |
 Existing authenticated platform APIs
            |
   Work session + Tracked task
            |
    Session state/activity/exit hook
            |
    Coalesced durable observation queue
            |
    Read rendered output + native final
            |
  Evidence assessment + Notification outbox
```

后台 Worker 当前随 API 进程运行，以便复用进程内 Agent 生命周期和状态跟踪器；消息处理、观察和通知是独立并发队列，慢模型请求不会阻塞观察与投递。当前每个数据库应只运行一个 API/Worker 实例，尚不支持多实例共享数据库调度。队列、上下文、工具检查点、任务和通知存入 SQLite，重启后通过租约恢复。

每次工具执行保存操作记录；模型或网络重试会复用工具结果。对中断期间结果不明的写入，不自动重发。新开发会话的操作引用写入会话任务元数据，用于核对原会话。模型最后回复已持久化但消息尚未确认时，恢复直接完成原回复，不重新运行工具。

外部消息按至少一次处理设计，使用消息 ID 去重。通知按至少一次投递设计；通用网关通过稳定投递 ID 去重，腾讯渠道在缺少强幂等接口的情况下，极端网络中断仍可能导致重复通知。

## 信息传递边界

信息在「用户 ↔ 企业微信 BOT ↔ 平台 AI ↔ 项目标签页 Agent」之间流动。平台 AI 负责路由、转发、查询状态与汇报，可依据用户上下文和已查证的事实补清背景，但不主观增加前置条件、限制或交付要求。查询 Jira 等任务先交给项目 Agent 检查现有配置；仅在 Agent 实际反馈缺少信息或提问后，转达具体问题，不提前要求用户提供地址、项目 key 或凭据。

派发工具从当前对话的原始用户消息读取需求，防止模型自行添加“只读”“禁止修改”、输出格式或验收标准。多轮需求通过 `source_message_ids` 按时间顺序关联原文，拒绝引用其他对话消息。

派发成功直接生成一句确认，不再调用模型编写流程说明或猜测后续计划。多标签进度优先用「标签页／状态／最近进展／最新更新（北京时间）」表格；单标签简短说明。`latest_update_local` 在服务端统一转换为 UTC+08:00，优先采用最近公开消息的时间，消息时间不可用时才回退到活动时间；查询和进程恢复不会把旧消息伪装成刚刚更新。

查询进度复用网页“对话”的 `GET /api/sessions/:id/conversation`，共享公开消息过滤、增量文件索引和权限校验，不再从终端输出或大段原生历史提取模型输入。项目概览每个标签只返回最新一条消息的 240 字符摘要；已知标签直接 `read_tab`，默认最多提供当前用户需求 240 字符与最新 Agent 进展 1000 字符。仅在短内容不足或用户要求详情时，使用 `detail=true`，最多取最近 12 条对话、正文合计 6000 字符。长消息保留首尾并标记省略，避免丢失末尾的提问和阻塞信息。

同一对话的保留工具历史中已有完全相同的消息与状态时，只返回 `unchanged=true` 和当前状态、更新时间，不重复正文。不会跨用户、跨聊天引用缓存；历史压缩后正文不在模型上下文时会重新返回。即使命中复用，也先重新校验权限并读取实时状态。网页实时状态栏的工具名称、命令概览和耗时仅用于界面，不进入平台 AI 的查询上下文。后台任务观察仍按任务引用读取公开消息增量，保留完成判断所需证据。

## 完成判断与效率

- 只跟踪登记并关联到对话/用户的任务；普通标签页的事件不会触发平台 AI。空闲、等待输入、退出事件优先触发检查；活跃输出事件合并节流，每次读取保存游标，并限制持久输出窗口。
- 观察队列使用持久化的 `next_observe_at` 合并事件，最多同时读取两个任务。启动时恢复活跃任务；没有事件时每五分钟做一次本地补偿。完成信号遇到原生日志延迟时最多短暂补查三次，不重复调用模型。
- 本地状态、输出和原生日志的轮询不调用大模型。无新增内容时不做 AI 进度分析；活跃输出按汇报间隔节流，非活跃输出按评估间隔节流。本次任务的新原生最终答复可及时触发分析，确认结果后不再跟踪。
- Codex 自动目标续跑的内部上下文不视为新用户需求，也不会交给平台模型；后续公开回复继续绑定原始任务引用。即使自动续跑让终端一直 busy，也会读取并评估新的原生答复，提问/受阻回复不受常规进度汇报间隔阻挡。空闲后的短暂补查次数耗尽后回到普通观察，不会永久跳过消息。受阻通知同时保留 Agent 原始回复。
- 用户要求“完成通知我”时，`track_session` 同样支持绑定了工作 Agent 的 terminal 标签：根据原生用户请求的稳定引用订阅本轮答复，不向标签写入命令、不创建巡检会话或定时任务。已经有结果时可直接通知；后续真实用户请求属于另一个执行轮次，不能借其结果证明本轮完成。
- 普通进度分析只提交本轮任务中 Agent 公开消息相对于上次成功分析的新增文本，最多 6000 字符，并附带有限的需求和前次摘要；完成分析直接使用已匹配本次任务引用的原生最终答复，不重复附带终端滚动日志。
- 空的增量读取保留游标；只有已有数据明确证明序号后退时才重建读取基线。重建是内部恢复，不单独向用户发送技术通知。相同任务状态和摘要使用稳定通知键去重；历史重复通知在对话中合并展示，底层审计记录保留。
- 通知用项目/标签名标明来源；已有 Agent 原始答复时直接转达，不再重复一份摘要或附加流程说明。原生答复受上下文读取长度上限约束，较长内容保留截断标记，完整会话可在项目标签页查看。
- 会话结束后仍通过授权的 display 接口读取归档的终端快照；缺少 CLI、失败退出等明确错误直接更新任务并通知。正常退出但没有本次需求的原生最终答复时标记结果待核对，不会一直显示执行中，也不会据此宣称完成。
- 交互授权/选择提示由程序标记受阻，不自动代替用户批准。
- 空闲、进程退出、`execute.completed`、定时任务 `success` 都不直接表示需求完成。
- 每次派发都附带唯一任务引用；新增 `GET /api/sessions/:id/completed-turn` 读取该会话原生记录中的最近一组用户输入/最终答复。只有用户输入包含本次引用，且完成依据确实来自该最终答复，才允许标记 `reported_complete`。历史最终答复、终端回显和日志中的完成示例不能通过该判断。
- 原生最终答复延迟写入时，会继续按评估间隔读取，即使终端没有新输出也会核对。原生记录不可读、任务未通过平台派发或无法绑定本轮输入时，保留 `uncertain`。
- 失败判断也需要输出中的连续原文依据；进程明确启动失败或取消时由程序记录会话失败状态。
- `reported_complete` 表示 Agent 报告完成，平台并未因此独立证明所有验收要求通过。任务同时保存摘要与证据；无法确定时保留 `uncertain`。
- 用户可以停止跟踪，不会因此终止 Agent。取消期间到达的旧评估不会重新激活任务。

定时任务复用原有调度器；通过平台 AI 创建的任务会关联源对话。每次发送前记录观察游标，每次成功派发创建跟踪任务，再汇报 Agent 后续结果；发送失败或条件跳过有独立通知。现有未关联平台 AI 的定时任务保持原有行为。

新建项目标签页遵循与手动创建相同的权限和数量限制，不因同项目其他标签页忙碌而阻止新建。补充或纠正已有需求时，`send_to_session` 通过 `POST /api/sessions/:id/input` 立即将原话提交到对应标签；即使标签忙碌或已有 `execute` 正在等待结果，也不等这一轮结束。输入按网页粘贴加 Enter 的方式提交，不发送中断、不清空输出、不取消已有等待；工作 Agent 决定如何处理追加消息。

该输入接口只串行化单次粘贴与 Enter 的短暂写入过程，返回 `submitted` 表示已经提交到终端，不代表任务完成。终端标签转发前检查当前确有 Codex/Claude 进程，避免把自然语言发到普通 shell。追加需求保留原任务与补充条件的跟踪上下文，用本次消息引用匹配后续答复，上一轮结果不用于证明新条件完成。平台权限、会话归属、实际交互确认和其他对话跟踪的边界仍会检查。

人工在网页输入、现有定时任务和其他 API 客户端仍可操作会话，当前版本尚未建立覆盖所有历史输入入口的统一消息邮箱；需要严格独占的任务应使用专用会话与独立工作目录。
