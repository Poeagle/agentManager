# API Key

在“平台管理 → 我的账户 → API Key”中填写名称、到期时间并逐项选择权限。只能授予当前账号拥有的级别；到期时间必须在未来。创建后立即保存密钥，页面关闭后无法再次查看。可在同一页面查看授权范围、到期和最近使用时间，并撤销密钥。

请求使用 `Authorization: Bearer <API Key>`。服务端只保存密钥的 SHA-256 摘要，每次请求都检查到期时间、账户状态、密钥权限和账户当前权限。权限收回立即生效；禁用账号、重置密码或撤销账号所有会话会删除其 API Key。每个账号最多保留 50 个密钥，包括已过期的密钥。

HTTP 接口按以下范围开放，接口原有的项目、会话和其他权限检查继续生效；未列出的路由默认不接受 API Key。

| 授权项 | 接口范围 |
| --- | --- |
| Agent API | Agent、会话、项目读取、定时任务、额度、上下文、文件、Git、任务、技能、事件和提示词增强 |
| 平台设置 | 设置、Agent 配置、Codex 环境、提示词增强配置 |
| 用户管理 | 用户管理接口 |
| 角色与权限 | 角色和用户角色分配接口 |
| 用户监控 | `/api/admin` 监控接口 |
| 项目授权 | 项目修改、删除和项目授权接口 |
| 添加项目 | 创建项目 |

某些接口同时需要多项权限。例如 Agent 配置接口也需要 Agent API 权限；更改受保护用户可能同时需要用户管理和角色权限。对只能读写的权限项，删除类业务操作使用写入级别。API Key 不可管理登录凭据、API Key 或个人共享资源，也不支持需要浏览器 Cookie 的 WebSocket 通道。

密钥应像密码一样通过安全渠道保存，使用 HTTPS 或本机回环连接传输，不放进命令行参数、日志或版本库。使用方应读取本地安全存放的环境变量或凭据文件，在请求头中提供密钥。
