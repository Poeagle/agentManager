# 同机 Codex 账号环境

Codex 的登录账号与 API Provider 是不同维度。平台可同时保留原有 API
Provider，并新增多个系统用户的 Codex 登录环境。两个环境可以使用相同的
`openai` Provider 和相同模型，平台通过稳定的环境 ID 区分账号。

本期只连接本机。项目仍在原来的本机目录；选用哪个账号环境，Codex 引擎及
工具命令就在该环境的系统用户下执行。不会复制 Codex 登录凭据、修改项目
ACL、配置 sshd 或替用户登录。

## 配置与预检

在 Agent 管理的 Codex 页面，点击“添加 Provider”，在同一表单选择“Codex 登录账号”，填写名称、系统用户名、
本机 SSH 端口、SSH 密码或私钥、Codex 命令和可选 CODEX_HOME。主机固定为
127.0.0.1。密钥方式支持平台进程的 SSH Agent、默认密钥或指定私钥文件；
密码通过 SSH_ASKPASS 传递，以平台密钥加密保存，不进入命令行参数、助手脚本内容或前端回显。
此处只填写可执行文件，例如 `codex` 或 `/home/ymchen/.local/bin/codex`，
不要添加 `--dangerously-bypass-approvals-and-sandbox` 等交互式 CLI 参数；
会话权限由平台设置。命令不在目标用户的默认 PATH 时填写绝对路径。

平台运行用户应已能用非交互 SSH 连接目标系统用户，且已确认本机主机指纹。
账号模式默认目标用户的 Codex 已登录，同时该用户能读写项目目录。SSH
必须允许 Unix socket 转发，目标环境需要 python3。平台使用严格主机指纹
检查；认证、主机指纹、连接、Codex 安装、未登录、引擎和目录权限错误会分阶段
显示。未登录只提示目标用户先运行 `codex login`，不会启动交互登录。

配置表单可在保存前预检 SSH、可执行文件、已有登录、模型列表和所选测试项目的
读写权限，保存后仍可在同一页面重新预检。新建标签页、切换账号时也预检目标用户对
项目目录的读写权限。这些检查不发送模型任务，不代表已验证一次真实模型响应。

引擎运行在目标用户的 `~/.agentmanager-codex/<平台与环境摘要>/`，日志和
PID 文件也在其中。SSH 隧道和受限历史缓存位于平台数据库目录的
`account-tunnels/` 和 `account-history/`，不会放宽原始历史目录权限。
平台退出时关闭自己的隧道，保留目标引擎；遇到未就绪的现存 PID，不会仅凭
PID 数字杀死进程。

保存后进入账号详情页，自动读取所选系统用户的 Codex 登录身份、版本、实际
可执行文件、CODEX_HOME、公开默认配置和模型列表；读取失败显示具体原因，已保存
配置仍可编辑。只返回白名单字段，不返回登录令牌、SSH 密码或完整原始配置。

## 使用权限

账号环境必须明确指定可使用的平台用户。未授权的普通用户看不到选择项，直接
请求该环境或关联会话也会被后端拒绝。平台管理员默认可见、配置和使用全部
环境，不受普通用户授权名单限制。已停用环境仍需先启用才能启动引擎。
普通成员还必须满足原有项目、会话归属和 RBAC 权限。

停用环境或撤销授权后，已有实时对话和原始终端连接会关闭，后续调用拒绝。
原有默认环境和 API Provider 未配置授权名单时沿用原有权限；管理员可另行
给它们设置名单或停用。已有历史会话的账号环境不能修改系统用户名或 CODEX_HOME；更换身份应新建环境，保证
旧历史可读取。点击“删除 Provider”时，弹窗才列出所有平台用户占用的标签页，包括空闲及已停止
但仍打开的标签页，支持单个和多选批量删除。配置页平时不展示占用表。正在执行或无法确认执行状态时禁止调整连接或重启；
空闲时可以调整。任何用户仍有占用标签页时都禁止删除 Provider。删除标签页先停止会话，
再清理各用户保存的标签页状态，保留历史；部分失败保留对应标签页并明确报告。
有历史记录的账号 Provider 删除后保留停用的内部历史路由，不再作为可选 Provider，
后续启动、输入和控制请求拒绝；历史记录仍可读取。

## 新建与切换

新建 Codex 标签页时可以选择有权使用的环境。当前标签页的“账号 / 接入”
选择器可在保留上下文的前提下切换环境；跨 Provider 选择模型也进入同一个
预检与历史复制流程。同一环境内切换模型、推理强度保留原有设置接口。

切换先确认原会话空闲、目标模型可用、项目及附件可访问，再复制完整原生
JSONL 历史，通过目标引擎 `thread/fork` 创建独立副本并验证恢复。不会用
用户与助手消息摘要代替工具记录，也不会自动提交新任务。验证通过后在原
标签页绑定新环境和原生会话，原会话保留为项目历史。准备失败保持原绑定；
目标终端启动失败通过原有生命周期恢复原环境、历史和附件。

完整迁移支持自包含的 legacy JSONL 和 paginated 历史。分页历史按原生
`history_base` 递归收集祖先的精确字节前缀，保留工具和压缩记录，不复制祖先后续
分支内容；导入副本采用新的等长 UUID，避免目标账号已有同 ID 历史造成冲突。
导入的祖先副本归档隐藏，但保留新会话恢复所需文件；不会归档原始会话。平台为
对话页面生成只读的完整历史视图，普通追加保持缓存 inode 和已有分页游标；实际重写
则重新读取完整页面基线，避免新消息覆盖旧消息。历史超过
1 GiB、祖先缺失、前缀损坏、自定义只读网络权限或目标用户无法读取原附件时明确报错，原
会话保留；不会静默创建空会话或改变权限。附件沿用本机共享路径，不复制
账号登录信息。

## 验证边界

自动化测试使用独立临时数据库、模拟 SSH、模拟 Codex RPC 和测试文件，
覆盖账号区分、授权名单、越权请求、连接错误分类、并发隧道复用、历史复制、
活动会话拒绝、目标失败清理、绑定回滚及前端流程。不依赖真实登录账号或
生产端口。部署前需要用实际已配置的 SSH 和已登录账号做一次人工连通检查。

问题与自动化用例的逐项对应、执行入口见 [Codex 回归测试清单](codex-regressions.md)。

### 账号详情与文件

账号 Provider 展示连接、登录、用量、运行占用、默认配置及模型能力；缺少的数据保持未知。SSH 预检位于连接设置后，可在保存前验证当前输入。

账号配置文件通过目标系统用户 SSH 访问：列出 `config.toml`、`AGENTS.md`、`AGENTS.override.md`，存在规则目录时列出 `rules/default.rules`，以及 `config.toml` 中指向 Codex 目录内的模型目录。仅具备设置写权限的用户可读取和编辑；敏感凭据文件和检测到包含凭据的文件不开放，目录外路径不开放。单个文件上限为 96 KiB，写入校验读取时的版本并原子替换；外部修改会导致冲突而不会被覆盖。文件修改后已有会话的配置不会自动迁移，Engine 启动配置在重启后生效。
