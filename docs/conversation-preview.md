# 对话视图与工作区

运行 `bash scripts/dev-conversation-preview.sh`。默认端口 43231；占用时直接报错，不停止其他服务。数据放在当前工作树的 `.test-data/conversation-preview`，使用独立数据库、登录 Cookie、tmux 命名空间。首次访问按界面创建试用账号。

AgentManager 在服务启动时接管 Codex Engine 生命周期，默认 Unix Socket 位于应用数据库同级的 `codex-engine` 目录，也可由 `AGENTMANAGER_CODEX_STREAM_SOCKET` 覆盖。平台记录 Engine PID、启动时间和日志；重启 Web 服务时验证并复用仍在运行的进程，进程不存在时才重新启动。生产环境会解除并禁用旧的 `com.ymchen.codex-engine*` launchd 作业，避免旧守护与平台同时管理 Socket。引擎的权限设置独立于终端 worker，因此管理员会话使用共享实时引擎；普通成员继续使用原有隔离终端与内嵌 CLI，并屏蔽共享引擎的 Socket 目录，保留原有文件权限边界。

每个 Provider 的侧栏卡片和设置页独立读取自己的运行时状态。页面显示实际启动命令和 argv；启动命令与附加参数可编辑，保存后只重启目标 Engine。启动、停止、重启和配置保存由服务端流式返回当前阶段、百分比和已完成步骤，失败时保留具体错误，不再用整份 Agent 状态覆盖所有 Provider。

对话页与终端连接同一个原生线程。新建时由引擎提交一次初始请求，终端随后连接该原生 ID，不重复提交。用户后续消息使用现有输入接口并标记 `source: conversation`，服务端直接向已加载的同一原生线程提交，避免终端菜单吞掉文本；未加载到此引擎的旧 CLI 保留终端输入路径。原生提交结果不确定时不会再向终端补发。显式停止会话会先中断远程引擎，再结束终端；重启 Web 服务只分离终端连接。

模型首段正文到达前，界面显示“等待返回正文”及从原生轮次开始计算的秒数；工具执行仅显示简短状态。收到正文片段后才显示“正文接收中”。连接状态仅表示事件通道可用，不表示模型已经产生正文。

参考 DeepSeek Harness 本地源码中的 `packages/api/session-controller/src/assistant-stream.ts` 和 `packages/client/ui-chat/src/client/chat/ChatView.module.css`：分开处理实时片段与持久化记录，使用稳定身份更新同一条消息；正文采用居中阅读栏，减少消息边框和元信息。

Codex 流式接入使用 [官方 App Server 协议](https://developers.openai.com/codex/app-server) 的 `item/started`、`item/agentMessage/delta`、`item/completed` 和 `turn/completed`。向浏览器发送用户消息回显、Agent 的中途进展（`commentary`）及最终回答（`final_answer`），两种正文都支持流式更新；不转发推理、工具参数或工具结果。事件每 10ms 合并一次。浏览器断线后读取最近一轮作为基线，再继续接收更新。

持久化回复由原生记录分页恢复。原生 turn ID 与 item ID 共同确定最终回复身份；同一轮次因收尾期间追问而产生的多个回答分别保留。`response_item` 与稍后到达的 `task_complete` 内容回声合并；不同消息或不同轮次中内容相同的回复仍各自保留。历史视图按需读取更早记录。旧的内嵌 CLI 无可订阅接口时会明确显示“尚未接入实时输出”，仍同步已完成的答复；Claude 暂保留此历史更新方式。管理员从对话发送消息时，若共享引擎明确返回 `notLoaded`，平台会先检查原生状态：空闲会话保留原生 ID 和历史、替换终端 wrapper 后接入实时引擎，再提交同一个客户端发送 ID；执行中的旧会话继续接收追问，并通过原生文件事件等到本轮空闲后接入。版本检查和停止前的状态复查失败时保留原任务；未知结果的提交不自动重发。待接入任务合并为每标签页一个文件监听，空闲安静 750ms 后复查，30 分钟到期或服务关闭时清理，不增加模型调用或周期轮询。普通成员仍保持原有隔离边界。维护接口 `POST /api/sessions/:id/streaming/enable` 仅允许会话所有者且具有 Agent 写权限时安排同一流程。

检查：`npm --prefix server test -- conversation-reader.test.ts conversation-stream.test.ts cli-command.test.ts`、`npm --prefix dashboard test -- SessionWorkspacePane.test.tsx ProjectViewNavigation.test.tsx`、`npx playwright test e2e/conversation-view.spec.ts` 和 `npm run build`。

## 阅读工具与内容渲染

## 消息顺序

消息按原生记录及事件中的先后顺序合并，时间戳只用于显示。点击发送时立即在末尾保留位置，并携带客户端关联 ID；原生回显先于 HTTP 确认到达时也不会重复追加。同轮次的相同追问分别匹配，Codex 实时用户消息与持久化记录的不同 ID 通过轮次内有序匹配建立别名。旧记录不能消耗新发送的相同文本，持久化后的答复也不会被过期的流式快照恢复为输出中。

## 对话附件

输入框提供附件按钮，支持选择文件、粘贴截图和拖入文件。上传期间显示进度；失败保留草稿和附件并允许移除，未成功上传时不能发送。对话与原始终端切换保留附件草稿。支持仅发附件，每条最多 8 个；图片合计最多 10 MB，单个普通文件最多 100 MB，所有附件合计最多 100 MB。

附件复用会话所属项目的上传接口，保存在 `.agentmanager/pastes`。提交时再次校验文件与真实路径，禁止任意主机路径或越界符号链接。共享 Codex 引擎通过原生 `localImage` 输入接收图片，普通文件以路径交给 Agent 读取；内嵌 CLI 保留文件路径输入方式。附件展示信息保存在应用数据库，图片通过原生图片输入提交；不再将 `<agentmanager_attachments>` 等内部标记写入模型或终端正文。普通文件使用可读的路径引用，旧内嵌 CLI 也使用可读路径。历史和实时接口通过原生图片路径或客户端消息标识恢复附件卡片，旧版本的附件记录仍可读取。对话记录不返回原生记录中的内联像素数据。

## 目录菜单与恢复后的消息身份

目录树菜单与删除确认框渲染在独立浮层中，终端处于前台、尚未打开文件时仍可操作文件、目录和空白区域；关闭菜单不切换当前会话。恢复过的 Codex 线程可能为历史和实时消息使用不同 item ID，合并时按同一轮次内角色、阶段、正文及顺序建立别名，保留确实重复发送的不同消息。重连时工具执行之前已经结束的进展不再标记为正在输出。

同一轮连续的 Agent 进展共享一个实时更新的进展区域，正文逐段追加，最终结论单独显示。用户追问或新的轮次开始时建立新的进展区域。原生消息 ID、章节锚点、复制和目录跳转仍按各条消息保留；界面只在当前实际输出的最后一条消息显示一个流式光标，工具执行与结束后不保留光标。

进展区域以时间线展示，每条显示组内序号、常显的本地时间（精确到秒）；当前实际输出的条目高亮。时间缺失时明确显示未知，不用读取时间代替历史发生时间。

## 原生执行错误

对话中独立显示模型容量不足、限流、连接错误等原生执行错误的原文及时间，提供查看原始终端和复制错误入口。读取实时 error 通知、turn/completed.error，以及历史 task_complete.error；按轮次、错误代码和正文稳定去重，刷新后保留。原生 willRetry 为真时显示自动重试；最终失败时停止执行中和光标提示，重试继续产生进展后结束旧的重试提示。原生任务以错误结束时，运行状态记为 failed。工具结果、推理和错误的私有附加详情仍不作为对话正文返回。


## 状态流和耗时

输入框上方固定一行展示当前执行步骤，来自已有实时事件中的命令、MCP 工具、文件修改或搜索摘要。新步骤向上切换，长文本在单行内滚动；减少动态效果的系统设置会关闭动画。仅保留最近八个活动摘要，不展示工具结果和内部推理，不调用模型生成状态。未连接实时事件时保持普通状态提示。

步骤耗时优先使用原生 startedAtMs/completedAtMs/durationMs，实时事件缺少时间时从该事件首次到达开始计时。重连时没有原生时间的历史步骤不伪造计时。进展条目只在同一轮相邻 Agent 输出之间显示间隔时长（不加“消息间隔”字样），不会跨过用户追问、错误或其他轮次计算；当前轮最后一条进展显示“距上次更新”。这些是消息记录之间的时间差，包含等待和暂停。最终答复显示最近用户发言至答复记录的“本轮耗时”。时间戳显示原生消息记录时间（本地时区），不作为阶段开始时间。缺少时间或时间倒退时不显示推测值。

## 对话中的确认和选择

原生 Codex 实时连接发送的提问会显示问题卡片，支持单选、选项说明、自定义文本和私密输入。回答全部问题后点击“提交回答”；普通答案草稿按账号、会话和请求隔离，刷新或切换视图后恢复，私密输入不写入浏览器存储。可稍后回答的请求不占用普通消息输入；阻塞请求处理前暂停消息发送。

命令执行、文件修改与额外权限申请显示确认卡片，可“允许本次”或“拒绝”，命令和文件确认还可取消；权限申请只授予当前轮。多个待处理请求按顺序展示。提交后锁定按钮，其他窗口或原始终端处理完成后卡片同步消失，重新连接时由原生服务重放仍待处理的请求。断线和只读账号禁用提交，服务端每次提交重新检查登录状态、会话访问权限和 Agent API 写权限。卡片只接受对应请求的结构化答案，不向终端写入猜测的按键，也不自动授权。

内嵌 CLI 或尚不支持的请求仍提供原始终端入口。终端正文中的编号、播放箭头和空闲输入光标不会当作选择题；已知原生执行状态优先于终端文本推断。

右侧目录预览上方以加粗、浅色底和侧边色条突出“你的问题”，下方保留 Agent 输出摘要与章节。点击问题定位到该次提问，点击摘要定位到回答，点击章节定位到具体段落。长问题在预览内换行、滚动，不撑开横向滚动条。

Codex 的 `request_user_input_async` 还会以 `AgentMessage.delivery = async` 和 `questions` 字段发出非阻塞问题，工具调用本身立即完成。此类消息在输入区显示选项与自定义回答卡片，正文保留可展开摘要，历史读取和实时消息都保留结构化字段；答案通过正常用户输入发送到同一会话，不冒充待处理 RPC 请求。提交不会清空输入框或附件草稿，后续已有用户发言的旧提问停止接收答案。仅凭编号文本或工具参数不会生成卡片。回归使用真实异步消息的字段形状，见 `e2e/conversation-async-questions.spec.ts`。

会话关闭弹窗提供“取消”“停止并关闭”“删除会话”，已移除后台隐藏标签的入口和回调。“停止并关闭”保留历史；“删除会话”先停止运行，再删除记录和保存的输出。只有操作成功才移除标签，失败保留页面并可重试。项目标签关闭时停止该项目的运行会话，保留历史；单个会话的永久删除由会话关闭弹窗或历史列表完成。`DELETE /sessions/:id/record` 默认拒绝活动会话，显式指定 `stop=true` 才会先停止并删除；每次仍校验账号所有权和项目工具权限。


对话的图片附件与 Markdown 图片均在当前页面的居中弹窗中预览，支持适应窗口、放大、缩小及放大后的滚动查看。Esc、右上角关闭或点击遮罩均可返回对话；弹窗打开时暂停对话自动追尾，关闭后保留阅读位置和草稿。图片与正文里的本地文件链接分别使用居中图片预览和只读文件预览；缩略图显示更紧凑，正文行高与段落、列表、表格间距适当缩小，代码区保留原有行高。


对话中的图片、文件附件和本地报告链接统一使用居中预览。图片可缩放或适应窗口；文件沿用只读的文档渲染器。Esc、点击遮罩或关闭按钮返回对话，保留草稿与阅读位置。

项目会话列表、展开的最近内容和管理监控摘要统一读取原生对话中的进展、结果及错误，摘要读取限制并发并短时缓存。原始终端仍可明确切换查看。管理监控中的关闭操作也会先停止会话，再移除标签，历史记录保留。

原生异步提问同时支持 `item_completed.AgentMessage` 和 `agent_message` 的结构化元数据。后一种格式从实际 `request_user_input_async` 调用关联原始问题编号；不依据问号、选项列表或工具输出推断提问。回答后折叠为摘要，并使用同一原生编号同步终端状态。


## 输入区的模型和会话信息

Codex 对话输入框下方提供模型、推理强度、上下文占比、周额度剩余和“详情”。型号及强度来自实际 `model/list`。选择直接调用与原生终端 `/model` 相同的实验性 `thread/settings/update` 接口；读取确认成功后显示“已应用”，并通过 `thread/settings/updated.threadSettings` 同步同一线程上的终端与网页。不提交额外用户消息、不启动新轮次，也不中断当前模型请求。旧版保存的待生效选择在进入该会话时同步一次；失败保留选择并提供重试。仅具有写权限的会话所有者可修改已加载的共享 Codex 会话，成员不会读取宿主账号的模型目录和额度。

详情显示实际设置、工作目录、当前 Git 分支及变更项、访问权限、当前实际加载的 Codex 服务版本，并区分最近一次请求和会话累计的输入、缓存命中输入、输出、推理输出 Token。上下文占比按最近一次原生请求的总 Token 与窗口容量计算，不拿累计用量计算；缺失字段显示“未提供”。原生额度记录及官方额度接口均只投影剩余比例、周期和重置时间，不返回账号余额或凭证。参考 [Codex App Server 协议](https://learn.chatgpt.com/docs/app-server)。

文件预览标题栏的“显示到侧边”把同一个只读预览器固定在对话右侧，释放遮罩和焦点限制；左侧可继续输入并发送反馈。“居中显示”可切回，保留文件滚动位置、已打开文件及输入草稿。窄窗口使用居中预览。展开详情和侧边预览在切换会话时退出，避免遮挡其他会话。

输入区底部的展示说明和“原始终端查看工具详情”常驻提示已移除，保留实际状态、操作入口与会话信息栏。


## 刷新、重载与紧凑输入

会话信息栏和详情共用缓存，每 5 分钟自动读取一次，窗口重新获得焦点不会提前刷新。两处均提供手动“刷新”，显式绕过模型目录、额度和 Git 状态的短时缓存。会话启动或重载完成时会按就绪事件补同步一次，避免初次读取过早导致控件一直禁用。此频率仅用于详情；正文仍接收原生实时事件。持久化记录通过文件变化监听及时补充已落盘的消息，支持旧内嵌 CLI；无新内容时不发送重复正文。有推送时 HTTP 历史读取降为 30 秒一次的补漏；通道不可用时保留原有短轮询。

输入框在光标位置以“图片 1、图片 2、文件 1”等特殊文字插入附件，与前后正文同行混排，仅在宽度不足或用户换行时换行。点击打开居中预览，上传成功后使用项目文件预览接口；不显示缩略图和移除按钮。文字是不可拆分的编辑原子，光标相邻或聚焦时 Backspace/Delete 删除整个附件；连续图片会重新编号。普通输入、中文输入法、换行和纯文本粘贴保留正常编辑行为。已经发送的消息也使用同行的可点击附件文字，不显示缩略图卡片。

标签栏提供“重载标签页”，先确认中断当前运行，再仅替换当前会话客户端。原生会话编号、历史、草稿和附件保留；并发请求只启动一个客户端，关闭操作可取消未完成的重载。启动前核对已安装 CLI 与共享引擎版本；不一致时保留原客户端并说明需先升级共享服务，不自动重启其他会话。详情与信息栏只展示当前连接的共享 Codex 服务版本，不再展示历史创建版本或混用已安装版本。

用户时间和复制按钮位于消息气泡内；Agent 进展的时间、用量和耗时独立放在正文上方；结论的统计信息与“Codex · 结论”标题同行，正文另起一行。只将“进展”“结论”文字突出为彩色标签，不给整块正文加卡片。结论的复制按钮放在统计行，进展不显示复制图标。空间不足时元信息自然换行，列表项目符号保持正常。自动注入的完整 AGENTS.md、环境、权限、技能及任务通知包装显示为紧凑的“自动信息 · 类别”入口，点击在居中弹窗中阅读 Markdown 并复制原文；压缩摘要使用相同交互。已识别包装去除外层标签后展示，环境 XML 保留代码格式；普通用户提问保持原样。自动上下文不算新的提问，不重置回答耗时和目录分组。

回归补充：`ConversationComposerEditor.test.tsx`、`conversation-context.test.ts`、`session-reload.test.ts`、`codex-version.test.ts`、`conversation-file-stream.test.ts` 和 `e2e/conversation-reload.spec.ts`。重载浏览器测试替换隔离测试客户端，不停止真实用户会话；原生模型设置另外通过独立测试线程和实际 Codex TUI 核对同步。


侧栏“优化当前输入”根据当前显示方式读取对话草稿或原始终端草稿。对话模式复用既有提示词优化接口及配置，先预览可编辑结果，再明确应用到输入框或复制；不会自动发送。取消、请求失败或切换会话均保留原稿和附件，草稿在请求期间变化时禁止覆盖。附件文字前只去掉原生正文末尾的空白，保留正文内部换行，避免原生记录末尾换行把图片挤到下一行。

附件位置作为文本字符偏移保存在现有附件元数据中，偏移值不写入模型正文。原生 Codex 输入同时携带对应位置的 `[Image #n]` 标记及 UTF-8 字节范围 `text_elements`，保留图文同行和用户明确输入的换行，不再由终端把无位置的图片统一放在正文前单独展示。发送时读取编辑器当前 DOM 位置，历史和实时消息使用相同元数据恢复；支持图片在正文前、段落中间及末尾，并保留同位置多个附件的顺序。旧记录没有位置时仍使用末尾展示。新数据无需数据库迁移，历史和刷新不再把所有图片自动移到末尾。


## 图表与当前标签页操作

文件预览、Markdown 可视编辑器、项目对话和平台 AI 回复支持 Mermaid 代码块；未标注语言但以 `flowchart TD` 等图表声明开头的代码块也可识别。图表可查看/复制源码、点击放大，语法错误时保留源码。普通代码保持原样。渲染器按需加载，在浏览器本地生成 SVG 图片，不执行图表脚本或加载外部图片。可视编辑器中可展开“编辑图表源码”，打开文件不自动改写或保存内容。

Codex 对话输入框下方的“压缩”调用原生 `thread/compact/start`；当前任务结束后可用，进度在会话活动行显示。“新开”经明确确认后在同一平台标签页创建新的原生会话，继承模型、推理强度和可确认的原权限，不携带旧对话，不启动模型回复；草稿与未发送附件保留。原会话保存为项目会话记录，附件、事件及任务历史关联转入旧记录。新会话预创建和持久化验证成功后才停止旧终端；启动失败时尝试恢复原会话。

旧会话停止当前执行、终端客户端和自身后台终端，浏览器切换订阅；原生 app-server 在无订阅和无活动达到其 30 分钟宽限期后回收线程内存。平台不为释放单个会话重启共享服务，也不自动归档用户原生会话及其后代。普通成员和未接入共享实时控制的会话不显示可操作状态，需先使用支持的原生终端或重载入口。会话详情仍每 5 分钟刷新一次，并保留手动刷新。

压缩状态由原生 `contextCompaction` 和 `turn/completed` 事件确认：输入框上方原有状态行显示启动中、压缩中及实时耗时；压缩按钮保持禁用和旋转图标，避免把 RPC 已受理误显示为操作完成。成功提示短暂保留，中断、失败和断线待确认分别显示，不增加提示行。终端中触发的压缩也会同步。上下文占用和 Token 计数接收原生 `thread/tokenUsage/updated` 推送更新；会话详情仍每 5 分钟自动读取，可手动刷新，不为压缩增加轮询。

压缩期间仍可正常发送文字与附件：平台使用原生 `thread/queue/add` 接收，压缩结束后由 Codex 自动开始处理；不通过终端粘贴重试，也不打断压缩。消息标注“已排队 · 等待处理”，排队列表通过初始读取与队列变化事件同步，刷新或重连后可恢复。提交关联 ID 与本机成功记录用于避免短暂断线下重复入队；原生用户消息出现后合并成一条并移除排队标记。只有传输状态未知才提示核对，明确拒绝单独处理。


## 统一文件预览

- HTML / HTM / XHTML 默认显示网页，可切换源码。本地 CSS、JavaScript、模块、JSON 与图片按当前项目边界读取；页面在独立来源 iframe 中运行，本地交互可用，不直接访问平台 Cookie 或后台接口。需要服务端接口、构建工具或开发服务器的页面仍需使用对应服务；资源或脚本失败会明确提示，不显示空白成功状态。
- Markdown / MDX 保留文本、文件跳转、图片、Mermaid、表格等。文档图片与 SVG 默认按可视宽高等比缩放，点击可以放大并返回原文；父级状态重绘不重建图片渲染器，不重复下载图片或重置 Blob URL。
- PDF、Word / RTF / ODT、演示文稿、Excel / ODS、CSV / TSV、draw.io 继续使用专用预览器；音频和视频使用浏览器原生播放器。媒体读取支持 HTTP Range，使用元数据预加载。字体资源可用于本地网页。
- 源码与文本仍可只读查看；无法读取或浏览器无法解码的文件保留明确错误及“下载原文件”入口，不执行项目中的构建或服务器程序。


## 用量与外部信息的刷新口径

点击“上下文”占用条可打开居中分类详情，原生最近一次用量与可见日志文本分类分开显示。分类在首次点击后按需读取当前账号 JSONL，30 秒内重开复用缓存，显式“重新读取”只读取日志；不会触发模型、额度或模型目录查询。分类采用字符数 / 3 粗估，未知工具定义及图片 Token 不编造，具体分类、压缩处理和资源上限见 [上下文分类](context-breakdown.md)。

上下文 Token 计数来自本机 Codex 的 `thread/tokenUsage/updated` 事件及原生日志。事件仅推送数值白名单，日志更新即使没有新对话正文也会同步；相同计数不重复发送。日志计数读取使用追加增量，不反复扫描完整历史。浏览器只更新用量缓存，避免每次 Token 变化都重新请求模型目录、账号额度和完整会话信息。压缩后的 Token 下降实时显示；较旧的详情请求不能覆盖较新的用量事件，新会话也不使用旧会话的计数。

模型目录与账号额度按五分钟缓存和刷新，手动刷新可显式绕过缓存；收到本地用量事件不会触发这些外部信息查询。网页与服务器之间仍有少量数值同步流量。读取计数不调用大模型；执行上下文压缩本身可能调用模型生成摘要。

压缩完成和原生线程 idle 状态会解除旧的忙碌标记，恢复压缩按钮；自动压缩期间若原生线程仍 active，则继续保持任务进行中，不允许再次手动压缩。按钮不可用时可通过提示查看实际原因。

详情优先展示上下文占用、本次与累计缓存命中率、本次输出，以及命中缓存/未命中输入的比例条，完整计数表按需展开。缓存率以缓存命中输入除以全部输入计算，累计比率使用累计输入加权；缺少计数、零输入或计数不一致时不编造百分比。推理输出已包含在输出中，不重复加总。


侧边文件预览支持拖动左侧分隔线调宽，键盘左右方向键也可调整，双击恢复默认。宽度偏好仅保存在浏览器；窗口变窄时保留对话可用宽度，调宽不重新挂载文件或重载图片、网页。

输入框和已发送消息的图片文字支持悬停缩略预览：停留 200 毫秒后加载图片，移开、滚动或切换会话时收起；点击仍打开可缩放大图。输入框优先使用已上传图片的本地 Blob，历史消息按需使用项目预览地址，不预加载所有图片、不增加定时刷新。


## 消息用量与工具统计

原生 Codex 日志中的用量事件按模型请求计数，一次请求可能包含多条消息和工具调用，因此不推算某句话独立消耗的 Token。进展显示本条请求区间的新增用量，结论显示上一次结论完成到本次结论完成区间内的新增用量。工具次数按原生请求 ID 去重，同一模型响应中多个并行工具记为一轮；Code Mode 内部调用不拆分。悬停统计可查看口径、模型请求次数。Token 包含重复上下文输入、缓存输入和推理，不表示金额。

统计首次最多读取日志尾部 2 MiB，此后共享增量缓存，并通过现有文件事件和 WebSocket 更新，只推送变化的数字元数据。不调用模型、不增加轮询。冷窗口没有覆盖轮次开头或数据不完整时，以 ≥ 标出窗口内已知下限，不推算完整总量；旧消息不全量回扫。

信息栏直接展示工作路径、Git 分支和变更、运行状态、权限、当前 Codex 版本、窗口容量及累计用量。用量和运行状态使用已有事件，目录/分支/版本等保持每五分钟和手动刷新。图片大图弹窗随原图尺寸及视口自适应，只保留少量内边距；放大后仍支持滚动，不按固定大画布给小图留白。

## 会话断线恢复

对话视图会暂停原始终端的浏览器连接以节省资源，因此不能依靠原始终端的重连回调判断是否可发送。对话 API 返回会话仍处于 running/detached、但 session_active 为 false 时，对话区会独立尝试一次连接现有终端，更新会话列表并重新读取就绪状态。失败时显示具体原因与“重新连接”按钮，保留输入草稿；已结束、待启动、释放到外部的会话不自动重启。

发送 API 同样检查是否需要接回存活终端，覆盖最后一次读取就绪状态后发生服务重启的情况。重连接口支持重复调用并返回当前会话状态；连接失败会在写入前明确拒绝，状态不明的已提交消息不会因此重复发送。

## 对话中的目录预览

点击项目内路径时，预览入口先通过受项目权限约束的 `/files/stat` 识别普通文件和目录，不根据扩展名猜测类型。对话里的项目外本地链接和 Markdown 图片也可以打开，使用当前用户的文件访问权限进行服务端校验；没有权限或文件不存在时显示错误。项目路径的符号链接别名按实际文件权限判断，项目文件树自身仍限定在项目目录。普通文件沿用现有预览；目录显示只读文件树，可按需展开子目录、单击文件预览、打开多个文件标签、刷新和显示点文件。文件树宽度可拖动，居中与侧边显示切换保留已展开目录和当前文件。关闭文件标签保留目录窗口。

目录浏览以选中的目录为根，继续沿用项目真实路径、符号链接和个人凭据文件的访问限制；不预读整个目录树，不提供写入入口。空目录正常显示空状态，路径删除和权限错误提供重新加载入口。目录符号链接在目标仍位于授权项目内时可展开。

进展独立统计行使用英文 `step · token: … · tools: … calls / … rounds`，统计上一条进展所在请求结束后、截至本条进展请求结束的新增用量；首条从当前轮开始计算。结论使用 `summary`，Token、工具调用数、工具轮数与耗时统一以“上一次结论完成 → 本次结论完成”为区间，首次从会话首次任务开始计算。中途追加用户消息、执行失败、自动重试和原生轮次切换都不重置该区间；耗时包含两次结论之间等待用户输入的时间。进展和结论区间基线分别保存在服务端增量解析状态中，结论携带开始、完成时间与区间耗时，不因分页、刷新或仅保留最近 80 条快照而误用累计值。日志窗口不全时以 `≥` 标出已记录下限；窗口内后续完整区间仍可准确计算。冷读保持 2 MiB 上限，找不到上一次结论或首次任务起点时不推算耗时，显示 `Total: —`；遇到下一条完整结论边界后恢复精确区间。

一次模型请求同时生成多条进展或多条结论时，无法可靠分摊到每条；显示 `shared`，悬停可看共享请求组用量，不给每条重复计算同一份费用。结论仍以各自的实际完成时间计算耗时。Token 仍以原生模型请求为结算边界，包含重复上下文和缓存，不等于单段文字生成成本。独立统计行的耗时、统计和提示文字使用英文，其他界面语言保持原样；未增加模型调用或前端轮询。


### 进展折叠与统计布局

“进展”“结论”文字使用醒目的彩色标签，正文保留平铺展示，不增加整块卡片边框。进展先显示独立的时间、Token、工具次数和耗时行，再显示正文；结论将这些信息放在标题同行，窄屏自然换行；进展仍在流式输出时仅提示 Streaming，完成后再显示统计。

已完成的进展默认折叠，正在执行的进展默认展开；用户手动收起后，新的流式片段不会将它重新展开。点击进展标题或使用键盘可以切换展开，结论始终展开。对话目录跳转到已折叠的进展或其章节时会先展开再定位。折叠使用浏览器原生 details，不触发网络请求，不删除对话数据。


### 标签页状态与回答接收

标签页状态复用已有原生会话事件订阅，执行开始、等待交互、完成、失败和中断事件同时更新全局状态；日志监听继续用于恢复历史和旧 CLI。只有状态变化才通知，全局文件监听按 80ms 合并，不增加原生连接、模型请求或周期轮询。实时状态的来源为 `codex_stream`，旧日志状态为 `codex_rollout`；已由原生事件确认的执行不再因终端进程检测缺失而降为未知。较慢的会话列表响应不能覆盖更新的推送状态，原生会话 ID 改变时不会沿用旧状态。

非阻塞问题的回答区分“正在提交”“已提交 · 等待接收”“回答已排队”和“已回答”。本地乐观消息不代表 Agent 已收到；只有原生用户消息回显后才显示已回答。原生服务确认提交或入队后，立即清除相应问题的待回答注意状态；压缩时已入队的回答继续显示等待接收，无需用户重复提交。队列回放可恢复排队状态；未消费的队列项被移除后恢复待回答提醒。服务端只保存有界、短期的原生问题 ID 和接收状态，不将回答正文放入状态广播。既有用户回复气泡仍是回答正文的唯一展示处。

当用户确认原始终端没有待保留的未发送草稿后，可通过会话重载请求的 `when_idle` 选项安排一次空闲后恢复。平台订阅原生会话事件，并在执行前再次验证会话状态、所有者与授权；执行时沿用现有空闲检查，不重发输入。等待项只保存在当前服务进程中，服务关闭或 24 小时后取消，需重新发起。

批量恢复仅在用户确认没有待保留草稿后，检查其本人 Codex 终端的当前屏幕，并安排重连已超时的终端；正常、无法检查和其他用户的终端不会重载。执行前会再次确认超时状态与授权，运行中的会话等待空闲。
