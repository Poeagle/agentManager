# 工作区交互与性能排查

覆盖项目和会话标签、Codex 账号与 Claude Provider、普通压缩与简要压缩、会话重连和刷新恢复。使用隔离的 Chromium、SQLite 和模拟 Agent 数据验证，读取本机实例的健康状态与加载结果。

| 场景 | 发现及处理 | 验证 |
| --- | --- | --- |
| 恢复与切换项目标签 | 启动时曾初始化所有已保存项目。现在首次打开项目时才初始化，已访问项目继续保留会话和终端状态。 | 五个已保存项目的浏览器场景中，首屏涉及的项目历史请求从 5 个降至 1 个。覆盖首次切换、切回、重命名、键盘和窄屏。 |
| 新建会话标签 | 点击项目行右侧的「＋」，按该项目的权限选择创建方式。窄屏从项目导航进入。创建成功后切到对应会话并刷新列表，使状态从待启动更新为运行中。 | 组件回归覆盖待启动会话，浏览器覆盖跨项目创建、取消、窄屏和 Claude Provider 创建流。 |
| 关闭项目和会话标签 | 项目关闭在检查运行会话期间显示进度。异步检查结束时按当前选中标签决定导航。 | 浏览器挂起检查请求后切换项目，确认关闭完成仍停留在用户刚选中的项目。另有停止保留历史、删除记录和刷新恢复覆盖。 |
| 切换账号或 Provider | 切换弹窗显示预检和切换进度。接口确认后立即显示新账号和会话，后台刷新相关数据。 | Codex 和 Claude 组件回归覆盖后台读请求迟迟未返回的情况。保留现有失败诊断和目标确认。 |
| 简要压缩 | 设置弹窗直接复用当前会话的账号与模型查询缓存。缓存新鲜时省去两次请求，缺失时按需加载。 | 组件回归验证打开后即可选择已加载选项。浏览器验证简要历史卡片可在刷新后恢复。 |
| 会话列表 | 查询最后活动时间时，依靠现有索引直接读取每个会话最高序号对应的输出时间。 | 50 个会话、25 万条合成输出的内存 SQLite 实验，查询中位耗时约从 27–33 ms 降至 0.1 ms。接口回归覆盖序号与写入顺序不一致以及无输出回退。 |

## 仍待量化的耗时

- Codex 跨账号迁移仍需读取源历史、在目标引擎恢复并核对。简要压缩仍需整理历史、创建新会话并确认首次发送。需要真实引擎、历史规模和附件分布才能测量各阶段及尾延迟，本次数据只覆盖隔离环境。
- 项目关闭仍从完整会话列表确认进程状态。有原生运行信息的前台项目也会同时触发全局和项目级会话列表轮询。列表查询优化只覆盖终端输出时间的读取，历史摘要与原生运行信息仍可能成为大工作区的主要耗时。
- 已访问的项目和终端为了保留交互状态继续挂载。PDF、Mermaid 和静态文档查看器的构建产物较大，首次打开及长期多标签场景的内存峰值仍需浏览器性能采样。
