# AgentManager 开发流程

本文件是 AgentManager 的仓库级开发流程规范。`AGENTS.md` 只作为 Agent 指令入口，具体流程以本文件为准。架构原则、Agent 接入、测试和界面要求见 [AGENTS.md](../AGENTS.md)。

## 工作区隔离

每个新功能、修复或独立验证任务必须从最新 `main` 创建自己的 worktree 和功能分支。主工作区与 `main` worktree 只用于同步和合并，不作为多个任务的共享开发目录。

```bash
git worktree add -b fix/example /path/to/agentManager-worktrees/example main
```

分支名应说明工作内容，例如 `fix/conversation-order` 或 `feat/agent-settings`。多个独立任务不能共用同一个功能分支或 worktree；后续任务从最新 `main` 重新创建。

开始任务时检查：

```bash
git worktree list
git status --short --branch
```

已有未提交改动必须保留，并确认它们属于当前 worktree 的任务。发现不同任务混在同一工作区时，先拆分或说明冲突，不能通过覆盖、丢弃或混入无关改动继续。

## 实现与验证

在任务 worktree 中完成实现、回归测试和必要文档更新。每次变更都检查是否影响 Agent API 的认证、权限、路由、请求或响应；有影响时同步更新 `getAgentApiContract()`、页面示例、版本与契约测试，并核对实现与契约一致。界面变更应优先节省空间，避免操作按钮单独占用多余行；检查窄屏下的换行与可用性，并主动整理发现的同类布局问题。按影响范围运行测试、类型检查和构建；检查差异，确认没有无关修改、密钥、个人数据或生成产物。

本次开发、测试或验证产生的临时资源应在用完后清理，最迟在同一轮交付前完成。包括临时文件、临时目录、测试数据库、测试账号与会话、进程、监听端口及其他测试环境，也包括在 worktree 之外、外部平台和服务器上创建的资源。只清理能够确认属于本次任务的资源，保留已有数据。交付前验证清理结果，无法清理时在交付说明中列出残留及原因。测试代码应优先使用隔离目录，并在成功和失败时释放资源。

Bug 修复应在能稳定复现问题的最低合理层添加测试。测试必须确定、隔离、可重复；不能依赖开发者数据库、真实账号、生产端口或线上服务。不能运行的检查必须说明原因和未覆盖风险。

## 合并与部署

验证通过后，通过代码审查或明确的合并流程把功能分支合入本地 `main`。验证失败时先修复，不以“稍后再测”作为合入依据。

功能分支合入本地 `main` 后，必须在同一轮立即清理。通过 merge、cherry-pick 或将 worktree 改动迁回 `main` 时均适用。确认本次改动已合入且 worktree 中没有需要保留的内容后，先移除任务 worktree，再删除本地功能分支。远程同名分支存在且已获授权时，同一轮一并删除。交付前用 `git worktree list` 和 `git branch --list` 确认清理结果，保留主工作区和 `main`。

合并后先确认 `main` 的提交和工作区状态，再按本机运行实例的加载方式完成交付。

- 运行实例能动态加载的改动，直接检查实际行为，确认生效即可。
- 需要构建、替换静态产物或重启的改动，从已验证的提交生成产物，同一轮部署到本机。部署后检查服务健康，并确认运行实例提供了新产物或呈现了修复后的行为。

## 推送

在 `192.168.0.104` 上开发的改动，验证通过并合入本地 `main` 后，必须在同一轮推送到 `origin/main`。推送后，用 `git ls-remote origin refs/heads/main` 核对远端提交。

推送使用 `ymchen` 账号。当前账号是其他用户时，先通过 SSH 登录 `ymchen`。其他开发机器上的推送、远端部署和其他远端写操作，须经用户明确授权。
